1. Vorbereitung lokal, beliebig vorher

Alles grün und gepusht lokal

Auf den Server kommt nur, was in Git ist.

make qa
git status          # nichts offen
git push
Lokale SQLite-Datenbank sichern lokal

Nur zur Sicherheit, bevor irgendetwas am Deployment ausprobiert wird.

make db-dump

2. Server einrichten einmalig, vor dem ersten Deploy

Port 7999 auf {{wgHost}} frei Server

Caddy bindet in compose.prod.yaml fest an {{wgHost}}:7999 – nur über diese Adresse erreichbar, nicht über alle Interfaces.

ssh {{sshSrv}}
ss -ltn | grep '{{wgHost}}:7999'    # darf nichts ausgeben
Ordner anlegen Server
ssh {{sshSrv}}
sudo mkdir -p /opt/advent
sudo chown "$USER": /opt/advent
GitHub-Zugang: Deploy-Key Server

Das Repo ist privat – ohne Schlüssel kommt Permission denied (publickey). Ein Deploy-Key gilt nur für dieses eine Repo und nur lesend; dein persönlicher GitHub-Schlüssel bleibt auf deinem Rechner.

ssh-keygen -t ed25519 -f ~/.ssh/advent_deploy -N "" -C "advent-server"
cat >> ~/.ssh/config <<'EOF'
Host github-advent
  HostName github.com
  User git
  IdentityFile ~/.ssh/advent_deploy
  IdentitiesOnly yes
EOF
cat ~/.ssh/advent_deploy.pub             # diese Zeile kopieren

Auf GitHub: Repo {{repo}} → Settings → Deploy keys → Add deploy key, Titel z. B. „Server“, die kopierte Zeile einfügen, „Allow write access“ aus lassen. Dann prüfen:

ssh -T git@github-advent                # „Hi {{repo}}! You've successfully authenticated…“
Code holen und Sicherungsordner anlegen Server

backups/ ist nicht im Repo (git-ignoriert) – ohne den Ordner scheitern Sicherung und Wiederherstellung. Existiert /opt/advent schon (z. B. von einem abgebrochenen Klon), erst leeren oder löschen – sonst meldet Git destination path already exists and is not an empty directory. Unbedingt vorher aus dem Ordner herausgehen (cd /) – sonst löscht rm -rf das eigene Arbeitsverzeichnis der Shell und git clone schlägt mit Unable to read current working directory fehl.

cd /                                                       # erst raus, sonst löscht rm das eigene Arbeitsverzeichnis
ls -A /opt/advent 2>/dev/null && sudo rm -rf /opt/advent    # nur falls der Ordner schon existiert und leer sein soll
git clone git@github-advent:{{repo}}.git /opt/advent
cd /opt/advent
mkdir -p backups/prod
chmod 700 backups

Klon schon einmal gescheitert? Macht nichts – /opt/advent ist dann noch leer, einfach erneut klonen.

.env.prod.local anlegen Server

Oben ausfüllen, dann unten in Abschnitt 6 den Block kopieren und hier einfügen.

cd /opt/advent
touch .env.prod.local && chmod 600 .env.prod.local

.env.prod.local danach zusätzlich im Passwortmanager sichern.

Stack starten und migrieren Server
make prod-up
make prod-status
Reverse Proxy auf {{wgHost}}:7999

Caddy ist nur an die WireGuard-IP {{wgHost}} gebunden, nicht öffentlich erreichbar – die Domain muss über einen vorgelagerten Reverse Proxy (z. B. auf einem VPS im selben WireGuard-Netz) auf {{wgHost}}:7999 weitergeleitet werden.

3. Go-Live erster Start in Produktion

Smoke-Test

Startseite öffnen, ein Türchen/eine Frage durchklicken, kein Fehler im Log.

curl -s http://{{wgHost}}:7999/
Logs kurz beobachten Server
ssh {{sshSrv}}
cd /opt/advent && make prod-logs

3b. Updates ausrollen bei jedem weiteren Deploy

Neuesten Code holen und ausrollen Server

make prod-up baut nur aus dem lokalen Checkout – es holt selbst keinen neuen Code. make prod-deploy macht beides in einem Schritt: git pull und danach make prod-up (inkl. Sicherung und Migration).

ssh {{sshSrv}}
cd /opt/advent && make prod-deploy

4. Direkt danach

Tägliche Sicherung einrichten Server
ssh {{sshSrv}}
crontab -e
30 3 * * * cd /opt/advent && make prod-backup >> backups/cron.log 2>&1
Uptime-Check anlegen

z. B. in Uptime Kuma: http://{{wgHost}}:7999/ (nur aus dem WireGuard-Netz erreichbar)

5. Nach einer Woche Aufräumen

Sicherung einmal probehalber prüfen Server
ssh {{sshSrv}}
cd /opt/advent && make prod-restore-test

6. Alle Werte für .env.prod.local zum Kopieren

Werte setzen Server

Setzt jede Zeile in .env.prod.local (alte Zeile mit demselben Namen wird ersetzt). Leere optionale Schlüssel bleiben aus. Beliebig oft ausführbar; danach make prod-up.


      

      
Enthält Schlüssel im Klartext – nur ins Terminal des Servers einfügen, nicht in Chats oder Dateien. Die erste Zeile hält sie aus der Shell-Historie heraus.
